# The leaderboard plan

One table for every entry of this repository's agent in the Gemma 4 Developer Agent competition: the commit, the one
change it measures, the evidence behind the change, and its score. Issue #126; the decisions behind it are in
[health-transformation-lab-nlp ADR 0007](https://github.com/healthtransformationlab/health-transformation-lab-nlp/blob/main/docs/adr/0007-gpu-hours-are-a-reserve-and-score-questions-go-to-the-leaderboard.md). Scores come from the ledger, [health-transformation-lab-nlp
`data/tasks/leaderboard_entries.csv`](https://github.com/healthtransformationlab/health-transformation-lab-nlp/blob/main/data/tasks/leaderboard_entries.csv), which a workflow there refreshes every two hours.

## The rules

- **One change per entry**, except the two final candidates (below). Each queued entry differs from the entry named in
  "Compared with" by one change, so the score difference is that change's effect. The public score is about 58 hidden
  tasks, and the same submission varies by about ±1.6 of them (paper track write-ups 91230 and 93326), so a difference
  of one or two tasks is noise; a change is judged on every entry and trace that bears on it, never on one score.
- **One pending entry at a time.** Kaggle refuses a new submission while one is pending ("Your team already has 1
  pending submissions"), and scoring machines are short (forum topic 747519). Entries go in this order, each when none
  is pending; an agent session's scheduled queue reads the order from this page.
- **Gates.** If E4B-all (which carries copyfix) scores 0.00 or errors, copyfix is suspect: the entries that carry it
  (5, 5b, 6, 7, 8) wait and versions without the adapter are proposed; 31B-d and 5c carry no copyfix and still go.
  If 31B-b runs past the 12-hour limit, its per-task budget is shortened before December 2, and 31B-c and 31B-d (the
  same 8-minute budget) do not go until it is.
- **The 31B comes second** (the owner, November 15, 2026: the main prizes can only be won with the 31B; the small model
  can win only the $10k bonus), so its first score and timing come before the small model's other changes. That slot was
  31B-b, the Budget-Fit budget, since the 5-minute 31B entry ran out of time on every task of its smoke test (#138);
  since #152 it is 31B-d, which carries 31B-b.
- **Three tasks or a repeat** (#142; the owner, November 15, 2026). With noise of ±2–3 tasks, an entry likely worth one
  or two tells us nothing and spends one of the 8–10 slots left. A slot goes to an entry where three or more tasks are
  plausible, addressing a failure in our traces, with evidence before it is submitted where that can be had; or to a
  repeat of one of the two final candidates, since the finals are chosen on reproducibility, running time and failure
  modes, not on one public score. An entry that fails this is held. Each row names its kill criterion: the result that
  stops further spending on it.
- **The 31B's time is measured before it goes** (#150; the owner, November 15, 2026). About 120 tasks at 8 minutes is 16
  hours, past the 12-hour limit, and every smoke-test task used its full time. A 10-task run of 31B-d at 8 minutes
  (health-transformation-lab-nlp #821) decides: a mean at or under 5 minutes a task, 31B-d goes at 8 minutes; above, its
  per-task time is capped so 120 tasks fit in about 11 hours (about 5.5 minutes). Until then 31B-d is held.
- **Entry 5 is skipped; 31B-d goes second** (#159; the owner, November 15, 2026, about 23:40 UTC). Entry 5 would hold
  the one slot for about 12 hours to check what E4B-all checks too, since it carries copyfix. 31B-d goes as soon as the
  timing run clears it; if it isn't cleared and submitted by 02:00 UTC on November 16, E4B-all goes at `204216e`, so the
  slot never sits idle for long.
- **Stacked final candidates** (#152, [ADR 0002](adr/0002-stack-changes-for-the-final-candidates.md); the owner,
  November 15, 2026). About 6 slots are left and one change rarely clears the noise, so the slots go to the two stacks:
  **31B-d** for the main prizes, second, once the timing run clears it, then **E4B-all** for the small-model bonus, once
  the skill-use check clears it (#156). Their parts are held: 5b is part of E4B-all; 31B-b and 31B-c are parts of 31B-d.
  A freed slot repeats whichever candidate is closer to its prize's line. A stack's score can't be split among its
  changes; if one scores below its kill criterion, it is split, starting with the part whose evidence is weakest.
- **The skill is checked in use before E4B-all goes** (#156). In the Modal colab-skill run (agent c7d68ea, 10 of our
  tasks on an L4, traces in Kaggle dataset `jcblearning/htlnlp-colab-official-colab-skill`), 0 of 10 tasks installed the
  skill or ran `find.py`, which hits 5b's kill criterion. #154 moved the install and `find.py` to the agent's first two
  calls, so E4B-all carries that commit (`a09e97e`). A 5-task E4B run on Modal (about $1, after the 31B timing run) must
  show `run_skill_script` in at least half the tasks; if not, E4B-all goes at `204216e`, whose skill is unused but
  harmless.
- **Built from a fresh checkout**, with no `__pycache__` or `.pyc` (the evaluator refuses them), named `submission.zip`.

## Why edits fail (the evidence for entries 5, 5b, 7 and E4B-all)

`analysis/edit_failures.py` reads each failed `edit_file` call's own error (#132), then compares each "old_string not
found" with everything the agent had seen in that trace. Over five development-set runs on the same 23 tasks (November
11, PR 100, PR 60, main at 8,192 and PR 107; traces from the kernels' output), `analysis/edit_failures.csv`:

| The tool's error, and the cause | Failed edits | What acts on it |
|---|---|---|
| **not found**, near_copy: a block it read is at least 95% alike | 28 | copyfix (5), `edit.py` (5b) |
| **not found**, paraphrase: 80% to 95% alike, rewritten from memory | 36 | short anchors and one re-read (7); `edit.py` refuses most, by design |
| **not found**, not_read: nothing it read is that close | 19 | short anchors and re-reading (7) |
| **not found**, seen_yet_failed: the exact text was in what it read | 7 | mostly a stale read: an earlier successful edit had changed the file |
| **not found**, whitespace_only or backslash_only | 0 | none needed: a whitespace- or escape-tolerant match would fix nothing |
| **ambiguous**: "Target string occurs N times", the anchor matched more than once | 25 | `edit.py --near` (5b: all 15 replayed applied); the rule to add a neighbouring line (7) |
| **other**: empty old_string, no change to apply, a tool error | 4 | |
| **All** | **119** | |

A shorter anchor fails "not found" less often (PR 117's statistics) but matches more than once more often: entry 7
trades one failure for the other, and its score is read with that in mind. The first version of this table (#126)
counted every failure as "not found" and put most ambiguous matches under seen_yet_failed; this one reads the tool's
own message.

## Choosing the two final submissions

One must be an E2B or E4B entry for the small-model bonus; it is the E4B entry with the most evidence behind it across
all entries and traces, not the single best public score, E4B-all the likely one. The other is the owner's choice,
31B-d the likely one. A repeat of either counts towards that evidence (ADR 0002). Both are chosen before December 2,
23:59 UTC.
