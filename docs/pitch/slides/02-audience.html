Who it's for, what we ask, what changes

Built for the people who build and score coding agents

WhoWhat we ask them to doWhat changes
Benchmark builders who mine tasks from a repository's historyAsk of every task: does its statement say what its tests check?A score is quoted on tasks that can tell one agent from another
Agent builders working with small local modelsRun their agent on the 93 tasks, with the competition's evaluatorA comparable score on health-data work, beside the popular libraries
Teams whose repositories are built with agentsKeep an issue, a pull request and a review for every changeTheir own history can become a task set

The impact: a task set that says which of its tasks can measure an agent. So far it is one repository and one model, and the screen is an AI's, checked by a person in part.

A personal project: no partner has been contacted

Three kinds of reader. People who build benchmarks from a repository's history: we ask them to check each task's statement against its tests before quoting a score, because here the fixes were almost all in the tasks that passed that check. People who build agents on small local models: the 93 tasks are public and in the competition's layout, so its evaluator runs on them as published. And teams whose repositories are built with agents: an issue, a pull request and a review for every change is what made this history usable. So far this is one repository and one model. A person checked 42 of the screen's 93 verdicts, in summary, and no partner has been contacted.
