Who it's for, what we ask, what changes

Built for people who build and test AI coding agents

WhoWhat we ask them to doWhat changes
Test builders who turn a code project's history into tasksCheck every task: does its description say what its tests look for?Scores are reported on tasks that can tell one agent from another
Agent builders working with small models that run on one machineRun their agent on the 93 tasks, with the competition's scoring programA score they can compare, on health-data code as well as popular libraries
Teams whose code is written with AI agentsKeep a written request, a proposed change and a review for every changeTheir own history can become a set of test tasks

The impact: a set of tasks that says which of its tasks can measure an agent. So far it is one code project and one model, and an AI did the check of the descriptions, with a person checking part of it.

A personal project: no partner has been contacted

Three kinds of reader. People who build benchmarks from a repository's history: we ask them to check each task's description, which the paper calls its statement, against its tests before reporting a score, because here the fixes were almost all in the tasks that passed that check. People who build agents on small local models: the 93 tasks are public and in the competition's layout, so its evaluator runs on them as published. And teams whose repositories are built with agents: an issue, a pull request and a review for every change is what made this history usable. So far this is one repository and one model. A person checked 42 of the screen's 93 verdicts, in summary, and no partner has been contacted.
